# finetune 包说明

## 作用

`finetune/` 目录当前承载两条链路：

* 旧版 Qlib demo 链路
* 当前 A/B/C 本地 CSV 实验链路

本文只说明代码职责、训练/测试口径和当前改动边界，不重复实验设计细节。实验目标与判定口径见 `zlab/lab.md`，执行流程见 `zlab/experiment_guide.md`。

## 旧版链路

旧版标准流程：

* `qlib_data_preprocess.py`
* `train_tokenizer.py`
* `train_predictor.py`
* `qlib_test.py`

训练逻辑：

* `train_tokenizer.py`：优化重建类 loss 与 `bsq_loss`，按 `val_tokenizer_loss_epoch` 选 best checkpoint
* `train_predictor.py`：优化 token-level 自回归 loss，按 `val_predictor_loss_epoch` 选 best checkpoint

测试逻辑：

* `qlib_test.py` 在测试集上生成 signal
* 再通过 `TopkDropoutStrategy` 做 Qlib 回测
* 主要输出是策略层结果，不是统一的收益预测统计指标

## 当前本地实验链路

### A/B

当前推荐链路：

* `csv_data_preprocess.py`
* `train_predictor.py`
* `evaluate_ab.py`

职责：

* `csv_data_preprocess.py`：从 `zlab/data/daily/*.csv` 生成 `train/val/test_data.pkl`
* `train_predictor.py`：冻结 tokenizer，部分解冻 predictor，做日线微调
* `evaluate_ab.py`：输出 `RankIC / IC / DA / MAE / RMSE / top-k / long-short`

### C

当前推荐链路：

* `csv_data_preprocess_c.py`
* `train_predictor_c.py`
* `evaluate_c.py`

职责：

* `csv_data_preprocess_c.py`：生成 `{"daily": ..., "hourly": ...}` 双流数据
* `train_predictor_c.py`：训练日线 predictor 上层 + 小时线 encoder/fusion
* `evaluate_c.py`：以与 A/B 一致的统计指标评估 C 组

## 当前相对旧版的主要改动

### 1. 数据接入改成了本地 CSV

当前不再依赖 Qlib 原始数据目录，而是直接使用：

* `zlab/data/daily/*.csv`
* `zlab/data/hourly/*.csv`（C 组）

同时补了几项实验需要的约束：

* `val/test` 自动带 lookback buffer
* 输出 `metadata.json`
* 输出 `symbol_stats.csv`
* 样本过滤按 `target_end_time` 落在正式 split 区间内进行

### 2. 训练协议从“全量 demo”改成“轻量任务适配”

当前 A/B/C 默认使用：

* `skip_tokenizer_finetune=true`
* `future_only_loss=true`
* `freeze_embedding=true`
* `predictor_train_last_ratio=0.333333`

A/B 环境默认还开启：

* `normalize_with_context_only=true`

即训练归一化只用历史 `lookback` 段统计量，与推理口径一致。

### 3. 评估目标从“回测优先”改成“收益预测统计指标优先”

旧版测试更接近 demo 风格回测。当前 A/B/C 的主评估指标是：

* `mean_rank_ic`
* `mean_ic`
* `rank_ic_ir`
* `direction_accuracy`
* `mae`
* `rmse`
* `topk_mean_return`
* `long_short_topk_mean_return`

也就是说，当前测试口径更接近“未来收益排序能力评估”，不是单纯生成 signal 后直接回测。

## 当前 B/C 的训练与选模口径

这一点需要单独写清楚。

当前 B/C 都是：

* 训练主损失：`future-only token loss`
* 每个 epoch 同时计算：`val loss` 与 `val mean_rank_ic`
* checkpoint 同时保存：
  * `checkpoints/best_model_by_loss`
  * `checkpoints/best_model_by_rankic`
* `checkpoints/best_model` 保留为 `best_model_by_loss` 的兼容别名
* 最终对比指标：`RankIC / IC / DA / MAE / RMSE / top-k / long-short`

因此当前实验结论应解释为：

* “在统一训练目标下，同时观察 loss 选模路径与 RankIC 选模路径的下游金融指标差异”

而不是：

* “只用一条 `val loss` 选模路径代表全部实验结论”

## C 组额外实现说明

C 组在现有 Kronos predictor 外新增：

* `models/hourly_encoder.py`
* `models/hourly_fusion.py`
* `models/kronos_with_hourly.py`

并通过：

* `dataset_c.py`
* `train_predictor_c.py`
* `evaluate_c.py`

完成双流训练和评估。

当前没有把 `csv_data_preprocess.py` 与 `csv_data_preprocess_c.py` 再抽成共享 helper。保持两个入口是有意的：B 和 C 的输出 schema 不同，当前先优先保证入口清晰和实验稳定。

## 日志与可视化

当前训练和评估日志会自动落盘：

* A 组推理日志：`zlab/results/evaluations/h*/<result_name_with_suffix>/inference.log`
* B 组训练日志：`zlab/results/models/h*/<save_folder>/train.log`
* B 组推理日志：`zlab/results/evaluations/h*/<result_name_with_suffix>/inference.log`
* C 组训练日志：`zlab/results/models/h*/<save_folder>/train.log`
* C 组推理日志：`zlab/results/evaluations/h*/<result_name_with_suffix>/inference.log`

当前 runner 还会自动追加参数后缀，避免不同 `pred_len`、不同训练参数或不同 checkpoint 选模路径互相覆盖。

TensorBoard 默认开启，本地目录为：

* `zlab/results/models/h*/<save_folder>/tensorboard`

Comet 已改为懒加载；关闭 Comet 时，不再要求环境里安装 `comet_ml`。
